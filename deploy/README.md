# Подготовка демонстрационного сервера

Деплой запускается вручную через GitHub Actions → **Deploy demo → Run workflow** из `main`. Перед публикацией выполняются проверки CI и сборка интерфейса. Само создание репозитория или push не запускает деплой.

Конфигурация рассчитана на отдельный VDS Ubuntu, PostgreSQL, nginx и процессы systemd без Docker. API слушает только `127.0.0.1:8000`. На сервере нужны Python 3.13, `uv` 0.13.6, отдельная база и пользователь `cybertech`. Настройки приложения хранятся в `/srv/cybertech/shared/demo.env`, а не в Git. Этот файл должен задавать `DATABASE_URL`, `MANAGER_PASSWORD`, `PUBLIC_URL`, `TRUSTED_ORIGINS`, `COOKIE_SECURE` и выбранный тестовый платёжный режим. Значения должны корректно читаться и shell, и systemd EnvironmentFile.

Для работы сценария нужно установить unit-файлы из этой папки, разрешить пользователю `cybertech` через sudo только команду `/usr/bin/systemctl restart cybertech-api.service cybertech-worker.service`, создать каталоги `incoming`, `releases` и `shared` в `/srv/cybertech` с соответствующими правами. Фронтенд собирается на GitHub; сервер устанавливает Python-зависимости из `uv.lock`. Выпуск сертификата, конфигурация HTTPS и тестовый SMTP-приёмник на сервере настраиваются отдельно до первой публикации.

В GitHub Actions требуются переменные `DEPLOY_HOST`, `DEPLOY_USER` и секреты `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. Ключ деплоя должен быть отдельным от административного, а ключ сервера — проверенным по независимому каналу. Скрипт создаёт новый каталог релиза, применяет миграции и начальные данные, переключает ссылку `current`, перезапускает API и worker и проверяет их состояние. При сбое перезапуска или проверки он возвращает предыдущую ссылку, если она существовала. Миграции базы автоматически не откатываются; перед изменением схемы нужно отдельно предусмотреть восстановление данных. Старые релизы сами не удаляются.

**Статус:** файлы подготовлены, но сквозная проверка GitHub Actions и сервера ещё не проведена. До неё не следует считать кнопку деплоя готовой к использованию.
